## Overview
Revision SDK is the Source SDK 2013 Singleplayer branch behind the Entropy: Zero (EZ1/EZ2) mods, carrying Mapbase v8.0 features plus the Expanded Steam integration; work here means writing C++ game code and shaders that compile into `client.dll` / `server.dll`.

## Tech Stack

- Language: C++ (Source Engine 2013 style, pre-C++11 idiom), HLSL and Valve `SDK_` shaders, a few Perl/batch/`sed` helper scripts
- Runtime / Framework: Source Engine 2013 singleplayer (`client.dll`, `server.dll`, VGUI2, VScript/Squirrel)
- Key Dependencies: Steamworks SDK (`sp/src/lib/public/steam_api.lib`, prebuilt), vendored protobuf 2.3.0, vendored Squirrel, Discord RPC, SDL2 (Linux GamepadUI only)
- Package Manager: none; builds are generated by Valve VPC (`sp/src/vpc_scripts`) into MSBuild `.sln` files or GNU `.mak` files

## Commands

Run everything from `sp/src`. Platform tooling lives in `devtools/bin` and is invoked by the wrapper scripts.

```
# Generate solution files (Windows)
createentropyzeroproject.bat   # entropyzero.sln (EZ1), entropyzero2.sln (EZ2), everything_entropyzero.sln
creategameprojects.bat         # games.sln (stock /hl2 /episodic targets)
createshadersprojects.bat      # shaders.sln
createmaptoolsprojects.bat     # maptools.sln
createallprojects.bat          # everything.sln

# Build (Windows, mirrors CI)
devenv games.sln /upgrade
msbuild -m -t:Rebuild -p:Configuration=Release;Platform=x86 games.sln

# Generate + build (Linux)
./createentropyzeroproject && make CFG=release -f <solution>.mak
```

- Verification is "it compiles". There is no unit-test, `make test`, or packaging target in this repo; testing means dropping `sp/game/mod_ez1` into `steamapps/sourcemods` and running the mod.
- Builds output to `sp/game/<GAMENAME>/bin` (`mod_ez1`, `mod_ez2`, `mod_hl2`) via `OUTBINDIR` in `game/client/client_base.vpc`. `sp/game/mod_ez2` is not committed, only the generated `bin/`.
- Visual Studio 2022 is required: `newer_vs_toolsets.vpc` enables only VS2022, and VPC still prints "Generating for Visual Studio 2013". If VPC fails on a missing registry key, import `vpc_scripts/newer_vs_toolsets_regkey_fix.reg`; CI also runs `reg add "HKLM\SOFTWARE\WOW6432Node\Microsoft\VisualStudio\10.0\Projects\{8BC9CEB8-8B4A-11D0-8D11-00A0C91BC942}" /v DefaultProjectExtension /t REG_SZ /d vcproj /f`.
- `phonemeextractor` and `qc_eyes` do not compile with VS2015+ toolsets and are excluded from the solutions.
- GamepadUI is external: `game/gamepadui/` holds one header and `BUILD_GAMEPADUI` defaults to `0`. Enabling it requires pulling `entropy-zero/HL2-GamepadUI` into that directory and flipping the `$Conditional` in `vpc_scripts/default.vgc`.
- `BUILD_EXPANDED_STEAM` also defaults to `0`; enabling it needs matching Steamworks headers and an updated `STEAMWORKS_VERSION` in `steamworks_update.vpc`, and the engine-side `bin/steam_api.dll` must be replaced.
- Shader content compilation needs Valve's `shadercompile.exe`, which is not in this repo, so `materialsystem/stdshaders/buildshaders.bat` cannot run standalone.
- Mod-specific code is isolated by preprocessor macros (`EZ`, `EZ1`, `EZ2`, `MAPBASE`); keep stock `hl2/` and `episodic/` paths intact when touching shared files.
